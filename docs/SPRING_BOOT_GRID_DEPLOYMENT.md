# Spring Boot + Grid deployment

## Why this deployment exists

The lightweight Node service under `preview-api/` exposes only stateless preview calculations. It does not run the job lifecycle, PostgreSQL persistence, RabbitMQ dispatch, worker registry or time-series scenario endpoints.

The full MVP console therefore targets the Spring Boot API at:

```text
https://perfusionlab-api.onrender.com
```

The console reads `GET /api/v1/health` and uses the returned `capabilities` list to decide whether Grid, ODE–PDE coupling and related controls are available. A preview-only API must never be presented as a functional Grid backend.

## Render topology

`render.grid.yaml` defines a separate full-stack Blueprint so the existing lightweight `render.yaml` deployment remains untouched.

| Resource | Purpose |
|---|---|
| `perfusionlab-api` | Public Spring Boot API and bundled web console |
| `perfusionlab-postgres` | Persistent job, outbox, batch and worker-registry state |
| `perfusionlab-rabbitmq` | Private broker with a persistent disk |
| `perfusionlab-worker-general` | GENERAL queue consumer |
| `perfusionlab-worker-memory` | MEMORY queue consumer |
| `perfusionlab-worker-compute` | COMPUTE queue consumer |

All application services use `backend/Dockerfile`. Render Postgres properties are mapped to the Spring datasource using `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` and `DB_PASSWORD`. RabbitMQ host and credentials are wired from the private broker service. Secrets are generated by Render and are not committed.

The three worker profiles are initially provisioned with the same 1 CPU / 2 GB compute plan and one slot each. They are separate logical queues and consumers, not claims of different hardware classes. Adjust plans and declared capacity together only after measuring workload and budget.

## Cost and approval boundary

This topology is **not a free-tier deployment**: it provisions paid API/worker compute, a paid private broker with a persistent disk, and managed PostgreSQL. The Blueprint is separate from the existing Node preview service. Review the Render plan and recurring charges before approving its first sync. Do not approve or provision infrastructure solely because this file exists.

## Local run

For a no-cloud-cost integration environment:

```bash
docker compose -f infra/docker-compose.yml up --build -d
```

The local stack starts the Spring API, PostgreSQL, RabbitMQ and three worker pools. Open `http://localhost:8080`.

## Smoke checks

Health and capabilities:

```bash
curl -fsS http://localhost:8080/api/v1/health
curl -fsS http://localhost:8080/api/v1/cluster/nodes
curl -fsS http://localhost:8080/api/v1/cluster/capacity
```

Generate a univariate temporal series:

```bash
curl -fsS -X POST http://localhost:8080/api/v1/simulations/timeline \
  -H 'Content-Type: application/json' \
  -d '{
    "baseline": {
      "pumpFlowLMin": 4.0,
      "hemoglobinGdL": 10.0,
      "arterialSaturation": 0.98,
      "systemicVascularResistance": 1200.0,
      "bodySurfaceAreaM2": 1.8,
      "temperatureC": 35.0
    },
    "parameter": "pumpFlowLMin",
    "endValue": 6.0,
    "durationSeconds": 60,
    "stepSeconds": 15
  }'
```

The response must contain five points at 0, 15, 30, 45 and 60 seconds, with the input and model outputs at every point. The UI plots and tabulates the returned `points`; it does not synthesize the time series in the browser.

Generate a multivariate temporal series:

```bash
curl -fsS -X POST http://localhost:8080/api/v1/simulations/timeline/multivariate \
  -H 'Content-Type: application/json' \
  -d '{
    "baseline": {
      "pumpFlowLMin": 4.0,
      "hemoglobinGdL": 10.0,
      "arterialSaturation": 0.98,
      "systemicVascularResistance": 1200.0,
      "bodySurfaceAreaM2": 1.8,
      "temperatureC": 35.0
    },
    "ramps": [
      {"parameter": "pumpFlowLMin", "endValue": 6.0},
      {"parameter": "hemoglobinGdL", "endValue": 12.0}
    ],
    "durationSeconds": 60,
    "stepSeconds": 15
  }'
```

These are didactic time-indexed evaluations of a static algebraic model, not physiological dynamic responses. No output is validated for clinical use.

## Frontend connection

- Local Docker Compose: leave the API base URL empty; the browser uses the same origin.
- GitHub Pages: use the deployed Spring Boot URL, `https://perfusionlab-api.onrender.com`.
- Other deployments: open **Configurações** in the console and enter the Spring Boot base URL.
- The Node preview service is not a substitute for the Spring Boot API. It must not be selected when Grid or timeline generation is required.
